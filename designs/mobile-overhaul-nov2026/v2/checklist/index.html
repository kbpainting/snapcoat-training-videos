Every control on these four screens, and where it is in round two

Before redrawing anything I listed every button, menu, filter, badge, dialog and rule on the four phone screens, straight from the app's code. Round two keeps all of it where it is today and changes only the look and the motion.

What is different from today, on purpose

This is the whole list. Nothing else moved.

  1. Sales Appointments, control row. Today the row holds seven controls but a phone only shows four. Progress, Cancelled and Add sit past the right edge of the screen. Round two keeps Refresh, Today, Calendar and Map exactly where they are and puts the three hidden ones on a second row right under them.Measured on the DEV site at 390 and 430 px wide: the three buttons start at 393 px.
  2. Project Calendar, button rows. Today "Schedule Project", "Daily" and "Legend" are partly cut off at the edges of the screen. Same buttons, same order, now sized to fit.Measured on the DEV site at 390 px wide: they run 9 to 24 px past the edge.
  3. Project Pipeline, stat tiles. Today the portfolio value and all four helper lines are cut short with "…". They are shown in full.Measured on the DEV site at 390 px wide.
  4. Long stage names and summaries wrap to a second line instead of being cut off.
  5. Dialogs rise from the bottom as sheets with a handle to pull down. Their titles, fields and buttons are unchanged.
  6. Emoji inside chips and badges are drawn as icons (Hot, Warm, Cold, Freezing, Paid, Unpaid, the goal milestones). The words stay.
  7. Small labels use normal capitalisation instead of all capitals.

Dropped from round one, because the app does not work that way: the bottom tab bar (navigation stays in the menu), dragging a card to another stage (cards move only through their own buttons, as today), and the swipeable stage rail.

Gaps I found in the app as it is today

None of these come from the redesign. I have not changed anything in the app. Tell me which ones you want fixed when this is built.

  • Sales Appointments: Progress, Cancelled and Add are off screen on phones. Adding is still possible from the Calendar view and from the pipeline's plus button. Today's Progress and Cancelled Appointments cannot be opened from this screen on a phone.Checked by measuring the live DEV page.
  • Project Pipeline: "Cancel Project" and "Unarchive" never show on phones. They exist for admins on desktop.Checked in the code: the phone card is not told the user is an admin.
  • Project Pipeline filters: only Tag filters anything. Project Manager, Project Status and Start Date Range can be set but do not change the board.Checked in the code.
  • Project card, "Assign to Project Manager": the list shows salespeople, admins and owners. People whose role is project manager are not in it. They can still be assigned from Project Details and from Schedule Job. The prototype shows project managers in this list.Checked in the code.
  • Tapping a date does not carry that date into scheduling, on either calendar.From the code inventory; I did not re-check this one by hand.
  • Project Calendar: Cancelled Appointments has no button on phones.From the code inventory; not re-checked by hand.
  • Sales Pipeline: unarchiving a lead shows the message "Lead Archived".From the code inventory; not re-checked by hand.
  • Sales Pipeline filters apply to lead cards only. Stage, source, proposal status, value, tag and date do not filter proposal cards. This may be intended.From the code inventory; not re-checked by hand.

How this was checked

  • A touch test taps through all four screens the way a finger would: 202 checks, run at three phone widths (360, 390 and 430 px), all passing. It confirms each control is present, in order, on screen, and does its job.
  • Every still was rendered in light and dark and reviewed for cut-off text, overlap and sideways scrolling.
  • Not checked on a real iPhone. All of this ran in Chrome's phone emulation. Blur and motion should be confirmed on a device before building.
  • Names, addresses and numbers are invented. Nothing here comes from customer data.
